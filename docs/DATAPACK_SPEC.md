# Chaos Hearts datapack: build spec

Pure Minecraft Java **1.21.11** datapack (pack format 94.1) plus a resource pack (format 75). No mods.
Function namespace `ch`, asset namespace `chaoshearts`. The datapack lives in `datapack/`, the resource pack in
`resourcepack/` (generated by `tools/gen_assets.py`). Repetitive datapack files are generated by
`tools/build_datapack.py` into `datapack/data/ch/function/gen/` (never edit `gen/` by hand).

The Fabric mod this was ported from is on git branch `fabric-mod`
(`git show fabric-mod:src/main/java/net/chaoshearts/ability/hearts/RageKit.java` etc.). Use it for intent and numbers,
then go further: the owner wants every move to feel unique, dangerous and cinematic.

## What the owner asked for (non-negotiable)

* **VFX must be out of this world**: so detailed it feels scripted. Layer display-entity choreography (custom
  tinted models that scale, spin and move with interpolation), dense particle shapes, dynamic light, screen
  overlays, camera shake and sound design on every move. A normal player should be astonished.
* **Hearts are real hearts.** Every Chaos Heart a player holds adds one heart (2 HP) of max health, and that
  heart is drawn on the health bar with its own icon (core does this). The Rage heart icon is a damaged,
  bleeding heart that feeds on taking damage.
* **No equippable items, no equipping by command.** There is no Focus item. Abilities are cast with key combos,
  and a hotkey shuffles which held heart is active (whose abilities you use).
* **Trials start at an indestructible altar structure** in the world.
* **Moves are unique and dangerous, and have variants.** Every ability has at least two variants chosen by
  how it is cast (look up, look down, moving). Telegraph big hits so a skilled opponent can react, then punish
  hard when they connect. You should feel you are truly in a battle.

## Controls (core implements; kits just read the variant)

All combos are *taps* (press and release within 6 ticks) while holding **Sneak**:

| Combo | Action |
|---|---|
| Sneak + Jump | Ability 1 |
| Sneak + Sprint key | Ability 2 |
| Sneak + double-tap Left strafe (A) | Ability 3 (mastery 40) |
| Sneak + double-tap Right strafe (D) | Ultimate (mastery 75) |
| Sneak + Back (S) | Shuffle to the next held heart (core) |

`/trigger cast set 1..4` also casts. Ability 2 unlocks at mastery 10.

Before calling a kit's `aN`, core sets **`#var ch.tmp`**: `0` level look, `1` looking up (pitch < -35),
`2` looking down (pitch > 35). **`#mov ch.tmp`** is `1` when the forward key is held, else `0`. Use them for
variants, for example Rage Leap: level = long leap, up = vertical rocket slam, down = instant ground pound.

Ability names, feats and skill-tree nodes are in `tools/hearts.json`. **Keep the ability names** (the HUD icons are

(any key may be left out). The generator merges it into the menus.

## Player state (scoreboards; read only unless noted)

* `ch.active` index of the active heart (0 none). `ch.lvl` mastery 0..100 of the active heart. `ch.awake` 1 if
  the active heart is awakened. `ch.b1 ch.b2 ch.b3` nodes taken in skill branches 1..3 of the active heart (0..5;
  node k of branch b is owned when `ch.b<b> >= k`; node 5 is the capstone).
* Unlocks: ability 1 at 0, ability 2 at 10, second passive (`p2`) at 25, ability 3 at 40, honed at 60 (core gives
  -15% cooldowns and +10% damage), ultimate at 75, aura at 90, trial at 100. Awakened adds the `aw` bonus.
* `ch.pid` player id. `ch.trial` > 0 while in a trial. `ch.cd1..4` cooldown ticks left (core counts down).
* **`ch.meter`** (kits write): 0..100 resource meter drawn under the ability icons in the heart colour (Fury,
  Momentum, Heat, ...). 0 hides it.
* Free per-player scratch: create your own objectives in `load`, always prefixed `ch.<h>.` (e.g. `ch.rage.fury`).
  Never use another heart's objectives. `ch.v1..v6`, `ch.t`, `ch.life`, `ch.owner` are for entities you summon.
* Fake players: `#now ch.g` gametime, `#t20 ch.g` (= gametime % 20), constants `#2 #4 #10 #20 #38 #60 #85 #100 #110
  #1000 #1200 #24000 #-1` in `ch.g`. Scratch: `ch.tmp` (any `#name`, never assume it survives a function call).
  Config: `#name ch.cfg` (see `gen/config_defaults`).

## Kit contract: `datapack/data/ch/function/kit/<h>/`

Every kit has all of these functions (an empty file is fine where nothing is needed):

| function | runs as / at | when |
|---|---|---|
| `load` | server | on load and /reload: create objectives (`scoreboard objectives add ch.<h>.x dummy`) |
| `tick` | each player whose active heart is this one, at them | every tick. Keep it cheap: gate work behind scores, use `#t20` for once-a-second work |
| `world_tick` | server | every tick. Drive your summoned entities here, guarded by `execute if entity @e[tag=ch.<h>.x,limit=1]` |
| `on_attack` | the attacker (tag `ch.caster`), victim tagged `ch.victim` | the player hurt something with a normal attack |
| `on_hurt` | the hurt player | something hurt them |
| `on_kill` | the killer (tag `ch.caster`) | they killed something |
| `equip` / `unequip` | the player | this heart became / stopped being active (add/remove attribute modifiers named `ch:<h>_...`) |
| `a1` `a2` `a3` `a4` | the caster (tag `ch.caster`), at them | cast. `return 1` on success, `return fail` when it can't be cast (no cooldown is used) |

On success core applies the cooldown listed in hearts.json unless the kit already set one with `ch:api/cooldown`.
Passives: `p1` always, `p2` at mastery >= 25 (check `@s[scores={ch.lvl=25..}]`), an aura at >= 90 (ambient VFX every
few ticks), awakened bonus when `ch.awake` is 1. Implement every skill-tree node of your heart (hearts.json branches)
and the four feats (`ch:api/feat {h:"<h>",n:0..3}` once the condition is met; keep progress in your own objectives).

Never use `title @s actionbar` (it is the HUD). Use `title subtitle`, chat or the FX API.

## Core API (`ch:api/...`)

Damage and control. Always go through these so PvP balance, honed, trials, XP and hit indicators work.

* `ch:api/hit {d:<tenths>}` as the target, caster tagged `ch.caster`. `d:60` = 6 damage = 3 hearts. Applies config,
  honed, PvP and trial scaling, credits the kill to the caster, plays the hit marker, gives mastery XP with diminishing
  returns. Adds 1 to `#hits ch.tmp` when it lands (reset `#hits` yourself before an AoE). Note vanilla i-frames: a
  second hit on the same mob within 10 ticks only deals the difference, so combine damage or space hits out.
* `ch:api/cc {effect:"minecraft:slowness",sec:3,amp:2}` as the target: crowd control; players and bosses get 50% and
  players become immune for 3 s after. Use plain `effect give` for small soft effects on yourself.
* `ch:api/stun {t:<ticks>}` as the target: rooted (no walking or jumping). Same scaling and immunity.
* `ch:api/push {s:<blocks per tick>,y:<lift>}` as the target, **executed positioned at the origin** of the push:
  knocks it away. Mobs get exact motion; players get a wind burst (fixed strength, s and y ignored). Bosses ignore it.
* `ch:api/pull {s:...}` same but toward the origin.
* `ch:api/leap {n:1..3}` as a player: launches them along their look direction with n wind bursts (vertical part
  follows pitch). `ch:api/blink {d:<blocks>}` as a player: teleports up to d blocks along the look, stopping before
  walls, leaving an afterimage.
* `ch:api/heal {n:<half hearts>}` as a living entity.
* `ch:api/cooldown {slot:1..4,t:<ticks>}` as the caster (config and honed applied).
* `ch:api/xp {n:...}` as a player: extra mastery XP (rarely needed; hits already give XP).
* `ch:api/feat {h:"rage",n:0}` as a player: completes a feat once (fails if already done).
* `ch:api/later {t:<ticks>,then:"ch:kit/rage/x"}` runs a function later as a marker left at the current position, with
  the owner tagged `ch.caster`. The new marker carries the tag `ch.lnew` until the tick ends, so you can add tags or
  scores to it right after the call (e.g. `scoreboard players set @e[tag=ch.lnew,limit=1] ch.v1 3`).
* `ch:api/proj {item:"minecraft:fire_charge",scale:1.0,speed:6,life:40,hit:"ch:kit/x/hit",step:"ch:kit/x/step",end:"ch:kit/x/end",pierce:0,ignore:"ch.powner"}`
  as the caster: an item_display projectile from the eyes along the look. speed = quarter blocks per tick. `hit` runs at
  the projectile with the targets tagged `ch.target` and the owner tagged `ch.caster`; `step` runs every tick, `end`
  when it dies or hits a wall (use `ch:api/noop` for nothing). The new projectile has tag `ch.lnew` until the tick ends,
  so you can restyle it (e.g. `data modify entity @e[tag=ch.lnew,type=item_display,limit=1] item.components."minecraft:item_model" set value "chaoshearts:fx/orb"`).
* `ch:api/ray {range:<blocks>}` as the caster: first entity in the look line gets tag `ch.target` (`#rayhit ch.tmp` 1),
  and a marker `ch.rayend` is left where it stopped (removed at the end of the tick).
* `ch:api/own` as a summoned entity: stores the caster's pid in `ch.owner`. `ch:api/tag_owner` as such an entity:
  tags its owner `ch.caster` (remove with `tag @a remove ch.caster` when done).

Targets: select with `@e[type=!#ch:ignore,tag=!ch.caster,tag=!ch.noability,distance=..R]`. Players in spectator or
creative are filtered by `ch:api/hit` itself. Tag any helper entity you summon with `ch.noability` (and use a
type from `#ch:ignore` when possible: marker, item_display, block_display, text_display, interaction, area_effect_cloud).

### FX API (`ch:api/fx/...`) — the building blocks of the spectacle

Tinted, emissive, interpolated display entities. `color` is a decimal RGB int (e.g. 14689835 for #E0262B). All of them
clean themselves up. Orientation comes from the execution rotation (`rotated as @s`, `facing ...`); model +Z is forward.

* `fx/sprite {model:"ring",color:16777215,s0:0.2,s1:6.0,t:8,life:10,spin:0,dy:0.0}` one tinted model at the current
  position/rotation, scale s0 -> s1 over t ticks, spinning `spin` degrees (max 170) around its own Y and rising `dy`
  blocks, removed after `life` ticks.
* `fx/sprite3 {model,color,a:"[x,y,z]",b:"[x,y,z]",t,life,spin}` same with non-uniform start/end scales.
* `fx/wave {color,r:6.0,t:8}` ground shockwave ring + dust ring at the feet; `fx/slash {color,s:3.0,roll:0,t:4}` a
  crescent slash in front following the look, rolled `roll` degrees; `fx/pillar {model:"beam",color,w:1.0,h:8.0,t:6,life:14}`
  a vertical column; `fx/beam {color,w:0.4,len:20.0,t:3,life:8}` a beam along the look; `fx/orb {color,s:2.0,t:6,life:10}`.
* `fx/burst {p:"minecraft:flame",r:1.0,n:30}` and `fx/ring {p:"...",r:3}` particle shapes.
* `fx/screen {o:"rage",color:"#E0262B",in:2,stay:6,out:10}` as a player: full-screen overlay (glyphs listed in
  `tools/glyphs.json`: vignette rage speed infernal void frozen storm blood titan celestial corruption flash eye awaken shatter).
* `fx/shake {s:1..3,t:<ticks>,r:<radius>}` camera shake for players within r of the position.
* `fx/light {t:<ticks>}` brief dynamic light (a light block) at the position if it is air.
* `fx/text {text:"CRIT",color:"#ff3030"}` floating combat text that rises and fades.
* Sounds: `playsound chaoshearts:<name> player @a ~ ~ ~ <vol> <pitch>`; list in `resourcepack/assets/chaoshearts/sounds.json`.

Models available for `model` (item models `chaoshearts:fx/<name>`, white and tintable): `ring ring_soft disc dome
slash beam orb shard spike rune bolt flame swirl star crack hex cube skull cloud feather`. Flat ones lie in the XZ
plane centred on the origin, 1 block across at scale 1; `beam spike flame` stand on the origin and are 1 block tall;
`slash` is a crescent around the origin opening toward +Z. Heart gems: `chaoshearts:heart_<h>`.

## Trial contract

Core runs the state machine (altar -> build -> intro cinematic -> 3 waves -> boss intro -> boss with phases at 50% and
20% -> victory or fail -> cleanup and return). Arena slot s is centred at (s*1024, 100, 0) in dimension `ch:trials`.
A session marker (tag `ch.session`) sits at the centre with `ch.slot`, `ch.state`, `ch.phase`, `ch.hid`, `ch.owner`
(challenger pid) and free `ch.v1..v6`. The challenger has tag `ch.challenger`. Trial functions in
`datapack/data/ch/function/trials/<h>/` run as the session marker at the arena centre unless noted:

| function | when |
|---|---|
| `build` | build the themed arena: floor radius <= 30 around the centre, y 96..130, walls/pillars/decor, lights. Use fill/setblock; it must fit in one tick (fill limit 32768 blocks per command) |
| `intro` | once when the intro cinematic starts (core moves a camera around; add VFX and title text) |
| `wave {n:1..3}` | spawn wave n near the centre. Run `function ch:api/trial/adopt` as every mob you spawn |
| `boss_spawn` | summon the boss and run `function ch:api/trial/boss {name:"The Bloodlord",color:"red"}` as it |
| `boss_tick` | as the boss, at it, every tick: attack patterns. Telegraph (ground marks, sounds, windups) then hit hard with `ch:api/hit` (tag the boss `ch.caster` first, remove after) |
| `phase {p:2..3}` | as the boss when it drops to 50% (2) and 20% (3) health: new patterns, arena changes |
| `ambient` | every tick of the fight: weather, particles, arena hazards |

The boss must be a real vanilla mob (it gets the bossbar, scaled health and `ch.boss`). Use `minecraft:scale`,
equipment, custom names and display-entity armour/crowns to make it unique. Players have the trial ward, so a lethal
hit fails the trial instead of killing them. Keep everything inside the arena; core removes all entities tagged
`ch.tmob` and clears blocks in the arena box afterwards.

## Rules for every function file

* Valid 1.21.11 syntax only: text components are SNBT (`{text:"x",color:"red"}`), gamerules are snake_case,
  attributes have no `generic.` prefix, `particle dust{color:[1.0,0.0,0.0],scale:1.0}`,
  `particle dust_color_transition{from_color:[..],to_color:[..],scale:1}`, `particle block{block_state:"stone"}`,
  `particle entity_effect{color:[r,g,b,a]}`. A macro line starts with `$` and must contain `$(var)`; a non-macro line
  must not start with `$`. Check commands against `/tmp/claude-0/ref/mc/commands.json` and ids against
  `/tmp/claude-0/ref/mc/registries.json` when unsure.
* Comment each file's purpose in one line at the top (like the existing core files).
* Performance: never run unbounded `@e` every tick per player; limit by `distance=..R` and `limit`.
* Run `python3 tools/lint_datapack.py` before finishing; fix everything it reports in your files.
